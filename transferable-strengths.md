# Transferable strengths

This page maps my experience to the role families where the evidence in this portfolio applies directly. Use it to locate the relevant case study quickly rather than reading the whole portfolio.

## Technical content strategy

I audit a content set, rate findings by severity, prioritize against customer satisfaction, freshness, page views, and support signals, then ship the fixes on a release cadence. I have retired and reorganized subservices, built an intake path for incoming requests, and instituted recurring quality gates. See [content strategy and audit](case-studies/content-strategy-and-audit.md).

## Developer and API content

I have written REST API reference content, API changelogs documenting version deprecation paths, Resource Manager and Bicep material, schemas, quickstarts, and tutorials. The pull-request record includes 63 pull requests classified as REST API, Resource Manager, Bicep, or schema work, 49 in a dedicated REST API repository, 17 quickstarts, and 48 tutorials. I verified content against the Azure REST API specification rather than against prose.

## Infrastructure and observability documentation

I owned Azure Monitor documentation across alerts, metrics, logs, data collection, agents, autoscale, health models, and Kubernetes monitoring. I validated procedures in clusters and virtual machines I built. See [infrastructure storytelling](case-studies/infrastructure-technical-storytelling.md).

## Cloud and AI product content

I was sole writer for three product areas: Azure Cost Management and Billing for seven years, Azure AI Video Indexer across 73 merged pull requests, and Azure Carbon Optimization across 25. The AI work covered feature launches, preview-to-general-availability transitions, Arc deployment, private connectivity, and security baselines.

## AI-assisted content production

I used Claude and GPT models for approximately 90 percent of my day-to-day work in my final nine months, operated company-developed agents through a Visual Studio Code harness with Model Context Protocol integrations, designed an autonomous documentation pipeline, and built my own extension and 50 agent skills. Every output passed human review and no AI system merged a pull request on my behalf. See [AI-native content production](case-studies/ai-native-content-production.md).

## Retrieval, answer engines, and search

I ran question-driven retrieval evaluation with reference answers and LLM-as-a-judge scoring, measured structural remediation, and delivered search-oriented content, metadata, navigation, and redirect work on a very large documentation property. See [search and answer-engine readiness](case-studies/search-and-answer-engine-readiness.md).

## Docs as code and GitHub collaboration

I worked in Git-based documentation for a decade, with 2,292 merged pull requests across 33 repositories and 4,289 public commits. I reviewed teammate work, contributed to a public open-source repository, synchronized content across repositories, and built a credential helper and pre-commit enforcement for my own workflow. Before GitHub I worked in structured XML authoring with modular topics, schemas, metadata, reusable content, and multi-output publishing.

## Content governance and operations

I enforced content standards, managed outsourced and vendor technical writers, corrected ownership metadata across repositories, maintained redirects and navigation through reorganizations, and contributed 44 pull requests that replaced broad administrator guidance with least-privileged role guidance.

## Customer education and technical learning

I authored all six modules in a Microsoft Learn learning path on controlling Azure spending, contributed 31 merged pull requests to Microsoft Learn training, monitored completion rates and assessment scores, reported results to management, and revised lower-performing modules until completion improved. One seven-unit module was localized into 17 languages. Earlier I designed and delivered classroom training for a Department of Defense logistics system at about 15 facilities for roughly 500 users, and built a computer-based program later adopted as the Department of Defense baseline.

## Cross-functional orchestration

I was brought into feature design rather than handed finished software, and delivered through private preview, public preview, and general availability alongside implementation. I worked directly and frequently with technical account managers, customer success managers, sales engineers, product managers, and engineering subject matter experts. I led a self-initiated automation hackathon, and I absorbed and triaged a departing colleague's entire backlog.

## Measurement

I treated customer satisfaction as a day-to-day operating metric with target objectives, prioritized work using satisfaction, freshness, and page views in that order, and authored Power BI reports and dashboards on established documentation telemetry datasets for roughly ten years to track content health and improvement priorities.
